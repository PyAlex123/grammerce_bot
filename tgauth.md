# Telegram Auth — интеграция бота с платформой Grammerce

## Идея

Когда пользователь нажимает «Зарегистрироваться» в боте — он должен попасть
на платформу и **автоматически войти или зарегистрироваться** без лишних шагов.
Бот уже знает кто этот человек (tg_user_id, username, имя) — нужно передать
эти данные на платформу безопасным способом.

---

## Как это работает (целевая схема)

```
Пользователь нажимает кнопку в боте
        ↓
Бот генерирует одноразовый токен (UUID) → сохраняет в БД (bot_auth_tokens)
        ↓
Бот открывает URL:
https://admin.grammerce.io/auth/telegram?token=UUID
        ↓
Платформа получает токен → делает запрос к боту (или смотрит в общую БД)
→ получает: tg_user_id, username, first_name
        ↓
Платформа находит или создаёт пользователя по tg_user_id
→ выдаёт сессию / JWT → пользователь залогинен
```

---

## Варианты реализации (от простого к надёжному)

### Вариант А — Простой (без токена, через URL-параметры)
Бот передаёт данные напрямую в URL:
```
/sign-up?tg_user_id=123&tg_username=alex&tg_first_name=Александр
```
**Плюс:** просто, быстро  
**Минус:** небезопасно — любой может подделать URL с чужим tg_user_id

### Вариант Б — Одноразовый токен (рекомендуется)
Бот создаёт токен, платформа его валидирует:
```
/auth/telegram?token=a1b2c3d4-...   (действителен 5 минут)
```
**Плюс:** безопасно, токен нельзя подделать  
**Минус:** нужен endpoint на платформе + новая таблица в боте

### Вариант В — Telegram Login Widget
Стандартный виджет Telegram на сайте платформы.  
Пользователь нажимает «Войти через Telegram» прямо на сайте.  
**Плюс:** официальный стандарт, верифицируется подписью бот-токена  
**Минус:** работает только на веб-странице, не из бота

## Что нужно проверить на платформе Grammerce

### 1. Модель пользователя
- [ ] Как называется модель? (`User`, `Account`, `Profile`?)
- [ ] Есть ли поле `telegram_id` (BIGINT)?
- [ ] Если нет — можно ли добавить миграцию?

### 2. Существующая авторизация
- [ ] Какой метод аутентификации используется? (JWT / сессии / OAuth)
- [ ] Есть ли уже вход через соцсети (Google, VK и т.д.)?
- [ ] Какой фреймворк? (Django, FastAPI, Laravel, Next.js?)

### 3. Маршруты (роуты)
- [ ] Есть ли `/auth/telegram` или аналог?
- [ ] Есть ли `/sign-up` — что он принимает (форма, JSON, query-params)?
- [ ] Есть ли API для создания пользователя программно?

### 4. Что происходит при переходе по текущей ссылке
Бот сейчас открывает:
```
https://admin.grammerce.io/sign-up?tg_user_id=123&utm_source=tgads
```
- [ ] Платформа вообще читает `tg_user_id` из URL?
- [ ] Или параметр просто игнорируется?
- [ ] Что видит пользователь — пустую форму регистрации?

### 5. Общая база данных
- [ ] Бот и платформа используют одну БД или разные?
- [ ] Если одна — можно сделать прямую запись в `users.telegram_id`
- [ ] Если разные — нужен HTTP API между ними

## Что нужно добавить в бот (после анализа платформы)

В зависимости от выбранного варианта:

**Вариант А:** только обновить URL в `bot/handlers/register.py` — добавить
`tg_username` и `tg_first_name` в параметры.

**Вариант Б:** добавить таблицу `bot_auth_tokens` и endpoint (или общую БД):
```python
# bot/db/models.py — новая таблица
class BotAuthToken(Base):
    __tablename__ = "bot_auth_tokens"
    token: UUID          # одноразовый ключ
    bot_user_id: FK      # ссылка на BotUser
    expires_at: datetime # TTL 5 минут
    used: bool           # использован?
```
