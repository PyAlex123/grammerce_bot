# Grammerce Bot — пуш-уведомления: интеграция с платформой

Документ к ветке `addPush`. Что бот делает сам и **что нужно настроить на стороне
платформы**, чтобы активационные пуши (спека [grammerce_push_notifications.md](grammerce_push_notifications.md))
заработали полностью.

---

## 1. Кто за что отвечает

**Бот делает сам (этот репозиторий):**
- Хранит воронку-состояние владельца и **раз в час** решает, кому и что слать.
- Логика целиком на боте: приоритет шагов, тихие часы (09:00–21:00 Ташкент), дедуп
  (≤2 отправки на шаг), язык (`ru`/`uz`), один активный пуш на человека.
- Шлёт текст + WebApp-кнопку. (Картинки — задел на потом, сейчас только текст.)

**Платформа делает:** отдаёт боту воронку-состояние вебхуком. Тайминг/тихие часы/дедуп
платформе считать **не нужно**.

---

## 2. Что должна вызывать платформа

### `POST /api/bot/funnel-state`
- Заголовок `X-Bot-Secret: <PLATFORM_BOT_SHARED_SECRET>` (тот же секрет, что у остальных ручек).
- Тело JSON, обязателен только `telegram_id`. Остальные поля **опциональны** — это частичный
  апсёрт (передавай только то, что изменилось).
- Ответ: `200 {"ok": true}`; `401` — неверный секрет; `400` — нет/битый `telegram_id`.

```json
{
  "telegram_id": "123",
  "product_count": 3,
  "training_completed": true,
  "trial_ends_at": "2026-06-15T00:00:00Z",
  "plan_paid": false,
  "store_created_at": "2026-06-01T10:00:00Z"
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `telegram_id` | string/int | **обязательно** — кого обновляем |
| `product_count` | int | число товаров (0 → пуш «добавь товар»; при 0→>0 бот сам ставит `first_product_at`) |
| `training_completed` | bool | пройдено ли обучение |
| `trial_ends_at` | ISO-8601 | конец триала (для пуша 4); `Z`/смещения допускаются, хранится в UTC |
| `plan_paid` | bool | оплачен ли тариф; `true` → **все пуши для владельца выключаются** |
| `store_created_at` | ISO-8601 | опционально; проставляет дату создания магазина, только если её ещё нет (бэкафилл) |

> `store_created_at` обычно уже известна боту из `user-registered` (см.
> [redesign_integration.md](redesign_integration.md) §2.1) — в `funnel-state` она нужна
> в основном для разового бэкафилла старых владельцев.

---

## 3. Когда вызывать (события)

Слать `funnel-state` при каждом изменении воронки владельца:

1. **Магазин создан** — сразу после регистрации, с `trial_ends_at` (и при желании `store_created_at`).
   Без `trial_ends_at` пуш 4 («триал заканчивается») не сработает.
2. **Добавлен первый товар** — `product_count` (>0). Включает переход на шаг 3.
3. **Пройдено обучение** — `training_completed: true`.
4. **Оплачен тариф** — `plan_paid: true` (выключает все пуши для владельца).

**Безопасная синхронизация (рекомендуется):** дополнительно слать батч `funnel-state` по всем
активным (`plan_paid == false`) владельцам раз в час/ночь — чтобы состояние бота не дрейфовало,
если событийный вызов потеряется.

**Бэкафилл (один раз после деплоя):** прогнать `funnel-state` по текущим владельцам — иначе бот
знает состояние только тех, кого увидит дальше.

---

## 4. Какие пуши получит владелец (для понимания)

| # | Когда застрял | Отправка 1 | Отправка 2 | Кнопка |
|---|---|---|---|---|
| 1 | зашёл, нет магазина | +24 ч от первого `/start` | +3 дня | «Создать магазин» (+ канал) |
| 2 | магазин есть, `product_count == 0` | +24 ч от создания | +3 дня | «Добавить товар» (+ канал) |
| 3 | товар есть, `training_completed == false` | +24 ч от 1-го товара | +3 дня | «Пройти обучение» (+ канал) |
| 4 | `trial_ends_at` близко | за 2 дня до конца | за 1 день | «Выбрать тариф» |

- Приоритет (один активный пуш): 1 → 2 → 3 → 4. Шаг 4 адресован владельцу, прошедшему 1–3.
- Кнопка ведёт в платформу WebApp-ом (`PLATFORM_WEBAPP_URL`, иначе `PLATFORM_URL`).
- Кнопка «Канал» во 2-й отправке пушей 1–3 — только если в `.env` бота задан `CHANNEL_URL`.

---

## 5. Настройки на стороне бота (`.env`)
- `CHANNEL_URL` — ссылка на канал для 2-й отправки (необязательно).
- Остальное (секрет, URL платформы, WebApp URL) — уже есть, см. [.env.example](../.env.example).

После деплоя на проде применить миграцию: **`alembic upgrade head`** (добавляет колонки воронки
и таблицу `bot_push_sends`; `create_all` колонки в существующую БД не добавляет).
