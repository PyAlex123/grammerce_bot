# Задача агенту по боту: кнопки в онбординг-сообщениях платформы

## Контекст
Платформа Grammerce шлёт владельцам магазинов уведомления **напрямую через @Grammerce_bot**
(токен `TELEGRAM_BOT_TOKEN`, метод `sendMessage`) — это онбординг-пуши, напоминания «застрял
на шаге» и напоминания об оплате триала. К этим сообщениям платформа прикрепляет inline-кнопки.

Кнопки уже настроены на стороне платформы так:

| Кнопка | Тип | Что делает |
|---|---|---|
| 🚀 Открыть платформу | `web_app` | открывает Mini App `https://grammerce.io/login` прямо в Telegram |
| 💳 Оплатить | `web_app` | то же — открывает Mini App `https://grammerce.io/login` |
| 💬 Написать в поддержку | `url` (deep-link) | `https://t.me/<username_бота>?start=support` |

**web_app-кнопки работают сами** (Telegram открывает Mini App) — по ним от бота НИЧЕГО не нужно,
при условии что домен `grammerce.io` прописан как домен Mini App этого бота (в @BotFather /
настройках Mini App). Если Telegram отклоняет отправку с web_app — значит домен/URL Mini App
отличается: сообщите платформенной команде правильный URL Mini App.

## Что нужно сделать в боте — обработать `?start=support`

Кнопка «Написать в поддержку» — это deep-link `?start=support`. При клике Telegram присылает боту
команду **`/start support`** (payload = `support`). Сейчас бот payload не разбирает и показывает
обычное приветствие — надо добавить ветку.

**Требование:** при `/start support` НЕ показывать приветствие, а открыть **тот же флоу, что кнопка
бота «Поддержка» / «Живой оператор»** — то есть открыть чат с менеджером (создать тикет и показать
приглашение «✍️ Напишите ваш вопрос — оператор ответит…», перевести пользователя в состояние
ожидания сообщения в поддержку).

Бот уже умеет разбирать deep-link payload для `register` (`?start=register`) — добавьте рядом ветку
`support`, переиспользовав существующую функцию поддержки.

### Пример (aiogram 3.x)
```python
from aiogram.filters import CommandObject, CommandStart

@dp.message(CommandStart(deep_link=True))
async def on_start_deeplink(message: Message, command: CommandObject):
    payload = command.args  # 'support' | 'register' | ...
    if payload == "support":
        await open_live_operator(message)   # ← ТА ЖЕ функция, что кнопка «Поддержка»
        return
    if payload == "register":
        ...  # существующая логика регистрации — не менять
    # прочие payload / обычное приветствие — как раньше
```
(Если используется `Command("start")` без `deep_link=True` — возьмите payload через
`message.text.split(maxsplit=1)[1]`.)

### Не сломать
- Обычный `/start` (без payload) — приветствие, как сейчас.
- `?start=register` — вход/регистрация, как сейчас.

## Как проверить (end-to-end)
1. Дождаться/спровоцировать онбординг-сообщение платформы (например, напоминание «застрял на шаге»).
2. Нажать **🚀 Открыть платформу** → должен открыться Mini App (страница входа/кабинет) прямо в
   Telegram, без браузерного «Перейти по ссылке?».
3. Нажать **💬 Написать в поддержку** → бот открывает чат с менеджером (тот же экран, что кнопка
   «Поддержка»), одно сообщение = один тикет.

## На будущее (опционально)
Если позже захотите, чтобы «Оплатить» открывал Mini App сразу на разделе «Тарифы», а не на входе —
платформа сменит URL web_app-кнопки на нужный путь Mini App (например `.../login?next=tariffs`),
когда вы подтвердите поддерживаемый параметр маршрута в Mini App.
