# Grammerce Bot — Краткое техническое описание

## Стек

| Компонент        | Технология                                  |
|------------------|---------------------------------------------|
| Язык             | Python 3 (async)                            |
| Framework бота   | **aiogram 3** (Telegram Bot API, long polling) |
| База данных      | **PostgreSQL 16** (через SQLAlchemy 2 async + asyncpg) |
| Миграции         | **Alembic**                                 |
| Конфигурация     | **pydantic-settings** (`.env`)              |
| HTTP-клиент      | **httpx** (async) — запросы к платформе     |
| Контейнеризация  | **Docker / docker-compose**                 |
| Тесты            | pytest + pytest-asyncio                      |

---

## Точка входа

`bot/main.py`:
1. `init_engine()` + `create_tables()` — инициализация БД, создание таблиц.
2. Создаёт `Bot` и `Dispatcher` (FSM на `MemoryStorage`).
3. Подключает `EventsMiddleware` (даёт каждому хендлеру `AsyncSession`).
4. Регистрирует роутеры **в строгом порядке** (порядок важен):
   ```
   operator → start → demo → register → support
   ```
   `operator` первый — он перехватывает сообщения из чата администратора.
5. Запускает long polling.

## Модель данных (`bot/db/models.py`)

| Таблица               | Назначение                                            |
|-----------------------|-------------------------------------------------------|
| `bot_users`           | пользователь: `telegram_id`, `username`, `language`, UTM (`source/medium/campaign`), `first_seen_at`, `last_active_at`, `registered_at` (метка первой регистрации на платформе) |

Все дочерние таблицы ссылаются на `bot_users` через FK.

## Ключевые механизмы

### Сессии БД (middleware)
`EventsMiddleware` оборачивает каждый апдейт в `AsyncSession`:
- кладёт сессию в `data["session"]`;
- `commit()` при успехе, `rollback()` при исключении.

### UTM-парсинг
`parse_utm()` разбирает deep-link `/start utm_<source>_<campaign>`
→ `source`, `medium="tg"`, `campaign`. Сохраняется один раз (не перезаписывается).

### Авторизация на платформе (`services/platform_auth.py`)
- `POST {PLATFORM_URL}/api/auth/telegram/issue`
- Заголовок `X-Bot-Secret: PLATFORM_BOT_SHARED_SECRET`.
- Тело: `telegram_id`, `first_name`, `last_name`, `username`, `photo_url`.
- Ответ: `consume_url` (одноразовая ссылка входа). Таймаут 5 с.
- Любая сетевая/HTTP-ошибка → `PlatformAuthError` → мягкое сообщение пользователю.

### Живой чат оператора (`handlers/operator.py` + `support.py`)
Состояние хранится **в памяти процесса** (module-level), сбрасывается при рестарте:
- `_current_user_id` — с кем оператор сейчас говорит;
- `_active_user_ids` — множество активных сессий.

Поток:
1. Тикет приходит в `SUPPORT_CHAT_ID` с кнопкой `operator:start:<id>:<username>`.
2. Оператор жмёт → бот связывает обе стороны, уведомляет пользователя.
3. `operator_relay_to_user` — сообщения админа → пользователю.
4. `relay_user_to_operator` (в `support.py`) — сообщения пользователя → админу
   (только если он в `_active_user_ids`).
5. Кнопка `operator:end` закрывает чат.

> ⚠️ Состояние чата process-local: при рестарте контейнера активные сессии теряются.

### Входящий webhook от платформы (`bot/web.py`)
aiohttp-сервер, запускается в `main.py` параллельно с long-polling (один event loop,
`AppRunner` + `TCPSite` на `BOT_WEBHOOK_HOST:BOT_WEBHOOK_PORT`).

Эндпоинт `POST /api/bot/user-registered`:
1. Проверяет `X-Bot-Secret` == `PLATFORM_BOT_SHARED_SECRET` (иначе 401).
2. Требует `telegram_id` в теле (иначе 400).
3. `get_or_create_user` → `mark_registered()` (дедуп по `registered_at`) →
   `log_event("register_complete")` → commit.
4. Если регистрация первая — шлёт админу (`SUPPORT_CHAT_ID`) сообщение с именем,
   UTM-источником (из БД бота) и временем. Повторные вызовы → 200 без отправки.

Контракт направлен платформа → бот (обратное направление к `issue_auth_link`),
секрет общий. Порт нужно открыть для платформы (см. docker-compose / инфра).

## Конфигурация (`.env`)

| Переменная                    | Назначение                               |
|-------------------------------|------------------------------------------|
| `BOT_TOKEN`                   | токен Telegram-бота                      |
| `DATABASE_URL`                | строка подключения к PostgreSQL (async)  |
| `SUPPORT_CHAT_ID`             | chat_id админа/чата поддержки            |
| `PLATFORM_URL`                | базовый URL платформы Grammerce          |
| `PLATFORM_BOT_SHARED_SECRET`  | общий секрет API (в обе стороны)         |
| `BOT_WEBHOOK_HOST` / `_PORT`  | адрес/порт входящего webhook (дефолт `0.0.0.0:8080`) |
| `DEMO_BOT_*`                  | ссылки на демо-боты по нишам             |

> Примечание по деплою: `docker compose restart` **не** перечитывает `.env` —
> нужен `docker compose up -d`.

## Деплой

- `Dockerfile` + `docker-compose.yml`: сервис `bot` + сервис `db` (postgres:16-alpine).
- `db` с healthcheck; `bot` стартует после готовности БД (`depends_on`).
- Развёрнуто на VPS через Docker Compose.
