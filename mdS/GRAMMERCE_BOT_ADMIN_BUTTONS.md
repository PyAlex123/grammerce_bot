# @Grammerce_bot — кнопки входа у админа + подтверждение входа суперадмина

> Спека для агента **маркетинг-бота @Grammerce_bot** (отдельный проект, токен `TELEGRAM_BOT_TOKEN`).
> Всё нужное на стороне платформы уже готово — менять её не надо.
> Базовый контракт входа описан в [BOT_AUTH_SPEC.md](BOT_AUTH_SPEC.md); здесь — что добавить.

---

## Задача 1. У админа должны быть те же две кнопки, что у обычных пользователей

Сейчас на `/start` пользователь с админским chat_id попадает в админ-ветку и **не видит**
кнопок входа на платформу. Нужно показывать их всем, включая админа.

### Что показывать

На каждый `/start` (включая админский путь):

```python
from aiogram.types import WebAppInfo, InlineKeyboardButton, InlineKeyboardMarkup

LOGIN_URL = "https://grammerce.io/login"

# has_shop и consume_url — из ответа POST /api/auth/telegram/issue
open_label = "🚀 Открыть платформу" if has_shop else "✅ Создать магазин"

kb = InlineKeyboardMarkup(inline_keyboard=[
    [InlineKeyboardButton(text=open_label, web_app=WebAppInfo(url=LOGIN_URL))],
    [InlineKeyboardButton(text="🖥 Открыть на компьютере", url=consume_url)],
])
```

### Правила

- **Админ-меню остаётся.** Две кнопки входа добавляются к нему, а не заменяют его.
- **`consume_url` регенерируется на каждый `/start`.** Он одноразовый и живёт 5 минут;
  показывать старое сообщение из истории чата нельзя — ссылка уже потрачена.
- **`/setdomain` в @BotFather** должен указывать на домен платформы, иначе WebApp
  не отдаст `initData` и бесшовный вход не сработает.
- Первая кнопка (WebApp) — основной путь: платформа сама авторизует по `initData`,
  без одноразовых токенов и без ошибок `auth_expired`.

### Как получить `consume_url` и `has_shop`

```http
POST https://grammerce.io/api/auth/telegram/issue
X-Bot-Secret: <PLATFORM_BOT_SHARED_SECRET>
Content-Type: application/json

{"telegram_id": "123", "first_name": "...", "last_name": "...",
 "username": "...", "photo_url": "...", "lang": "ru"}
```

Ответ: `{"token", "consume_url", "expires_at", "has_shop", "needs_setup"}`.

## Задача 2. Подтверждение входа суперадмина с компьютера

**Что изменилось на платформе.** Суперадмин платформы теперь входит только через свой
личный Telegram-аккаунт (пароля у него больше нет). Из-за этого путь «Открыть на
компьютере» для него **перестал логинить сразу**.

**Почему.** `POST /api/auth/telegram/issue` доверяет только заголовку `X-Bot-Secret`,
а `telegram_id` принимает из тела запроса. Кто угодно с этим секретом мог бы выпустить
ссылку входа на суперадминский id — и получить админку. Поэтому для суперадмина
добавлен второй фактор.

### Как это работает

1. Суперадмин жмёт «🖥 Открыть на компьютере» → открывается страница «Подтвердите вход
   в Telegram» (она сама опрашивает статус).
2. Платформа **сама** шлёт суперадмину в личный чат сообщение с IP, устройством и
   inline-кнопкой «✅ Подтвердить вход» (обычная `url`-кнопка).
3. Он жмёт кнопку → страница на компьютере открывает `/admin` автоматически.
4. Окно подтверждения — **60 секунд**.

### Что требуется от бота

**Ничего кодить не нужно** — сообщение отправляет платформа через `TELEGRAM_BOT_TOKEN`,
кнопка обычная `url`. Требования только эксплуатационные:

- Бот **не должен перехватывать или подменять** эти сообщения.
- `TELEGRAM_BOT_TOKEN` на платформе и в боте — **один и тот же** аккаунт бота,
  иначе сообщение не дойдёт (и подпись `initData` не сойдётся).
- Суперадмин должен хотя бы раз написать боту `/start`, иначе Telegram не даст
  отправить ему сообщение.

### Обычных пользователей это не касается

Для не-суперадминов «Открыть на компьютере» работает как раньше: `consume_url`
логинит сразу, без подтверждения.

## Безопасность: как обращаться с `PLATFORM_BOT_SHARED_SECRET`

Этот секрет — единственное, что защищает `issue`. Утечка позволяет выпустить ссылку
входа на любой telegram_id (для суперадмина её теперь гасит подтверждение, для
владельцев магазинов — нет).

- Хранить только в env бота, не в коде и не в репозитории.
- Ротировать при любом подозрении — и одновременно на платформе, и в боте.
- Если суперадмину пришло сообщение «вход с компьютера», которого он не инициировал,
  — это признак утечки секрета. В тексте сообщения об этом сказано прямо.
