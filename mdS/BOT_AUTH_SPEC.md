# Grammerce — авторизация из маркетинг-бота @Grammerce_bot (спека для агента бота)

> Задача: убрать ошибку `auth_expired`, сделать вход бесшовным и добавить вход с компьютера.
> Все нужные эндпоинты на стороне платформы уже готовы (этот репозиторий). Здесь — что
> должен делать **маркетинг-бот** (отдельный проект). Токен бота = `TELEGRAM_BOT_TOKEN`.

---

## Что уже готово на бэкенде (менять не нужно)

### 1) `POST /api/auth/telegram/issue` — выдать одноразовую ссылку входа (для браузера/ПК)
Заголовок `X-Bot-Secret: <PLATFORM_BOT_SHARED_SECRET>`. Тело:
```json
{ "telegram_id": "123", "first_name": "...", "last_name": "...", "username": "...", "photo_url": "...", "lang": "ru" }
```
Ответ (200):
```json
{
  "token": "uuid",
  "consume_url": "https://<домен>/api/auth/telegram/consume?token=uuid",
  "expires_at": "…",
  "has_shop": false,      // ← НОВОЕ: есть ли у пользователя магазин
  "needs_setup": true     // ← НОВОЕ: нужен ли онбординг (магазина нет)
}
```
`consume_url` — **одноразовая**, живёт 5 минут. Открывается в обычном браузере и логинит в кабинет.

### 2) `POST /api/auth/telegram/webapp` — бесшовный вход (Telegram Mini App) ← ГЛАВНОЕ
Тело:
```json
{ "init_data": "<Telegram.WebApp.initData>" }
```
Проверяет подпись `initData` токеном `TELEGRAM_BOT_TOKEN`, логинит по `telegram_id`, возвращает:
```json
{ "token": "bearer", "shop_id": 12, "needs_setup": false, "lang": "ru" }
```
**Не одноразовый, без TTL-ловушки** — сколько угодно повторных входов, `auth_expired` не бывает.
Этот эндпоинт уже вызывается фронтом `https://<домен>/login` автоматически, когда страница
открыта как Mini App (см. ниже). Боту его дёргать НЕ нужно — достаточно открыть WebApp.

---

## Что должен делать бот (изменения)

### A. Кнопка входа = Mini App на `https://<домен>/login`  (решает #2, #4 — бесшовно)
Открывать платформу как **WebApp** (Mini App), а не обычной ссылкой:
```python
from aiogram.types import WebAppInfo, InlineKeyboardButton, InlineKeyboardMarkup
LOGIN_URL = "https://<домен>/login"   # тот же домен платформы

InlineKeyboardButton(text=open_label, web_app=WebAppInfo(url=LOGIN_URL))
```
Что произойдёт: страница `/login`, открытая внутри Telegram, сама возьмёт `Telegram.WebApp.initData`,
отправит на `/api/auth/telegram/webapp`, получит сессию и **сразу откроет кабинет** — без формы
логина и без одноразовых токенов. Повторные открытия работают всегда.
> Требование Telegram: в @BotFather выполнить `/setdomain` и указать `<домен>` — иначе WebApp
> не отдаст `initData`. WebApp-кнопку должен показывать именно бот с токеном `TELEGRAM_BOT_TOKEN`
> (подпись initData проверяется этим токеном).

### B. «Создать магазин» и «Открыть платформу» — одно и то же действие (решает #1, #3)
Это одна кнопка, отличается только подпись — по флагу `has_shop` из `issue` (или по своим данным):
```python
open_label = "🚀 Открыть платформу" if has_shop else "✅ Создать магазин"
```
- нет магазина (`has_shop=false`) → «Создать магазин»
- есть магазин (`has_shop=true`) → «Открыть платформу»
Обе ведут в один и тот же кабинет (WebApp `/login`). После создания магазина следующий `/start`
покажет уже «Открыть платформу».

### C. Вторая кнопка — «Открыть в браузере (ПК)»  (решает #5)
Рядом с WebApp-кнопкой дать обычную url-кнопку с `consume_url` из `issue`:
```python
InlineKeyboardMarkup(inline_keyboard=[
    [InlineKeyboardButton(text=open_label, web_app=WebAppInfo(url=LOGIN_URL))],
    [InlineKeyboardButton(text="🖥 Открыть на компьютере", url=consume_url)],
])
```
Пользователь на телефоне жмёт WebApp (бесшовно), а чтобы зайти с компьютера — открывает/копирует
ссылку «Открыть на компьютере» в браузере ПК. `consume_url` одноразовый, поэтому…

### D. Регенерировать ссылку на каждый /start  (решает #2 для браузерного пути)
На **каждый** `/start` (или нажатие «Создать магазин») бот заново вызывает `issue` и показывает
свежие кнопки. Никогда не переиспользовать старое сообщение/ссылку из истории чата — старый
`consume_url` уже потрачен и даст ошибку. WebApp-кнопка (A) от этого не страдает.

## Итог по 5 проблемам
| # | Проблема | Решение |
|---|----------|---------|
| 1 | «Создать магазин» и платформа — разные ссылки | Одна кнопка/действие (B), обе → WebApp `/login` |
| 2 | `auth_expired` при повторном входе | Основной путь — WebApp (A, без токена); браузерная ссылка регенерируется (D) |
| 3 | Кнопка не переименовывается | Подпись по `has_shop` (B) |
| 4 | Заходит через WebApp, но снова логинится | WebApp initData → сразу кабинет (A), аккаунт привязан к telegram_id |
| 5 | Нет входа с компьютера | Кнопка «Открыть на компьютере» с `consume_url` (C) |

## Чек-лист внедрения в боте
- [ ] `/setdomain` в @BotFather → `<домен>` платформы.
- [ ] На `/start`: вызвать `issue` (X-Bot-Secret), взять `consume_url` + `has_shop`.
- [ ] Показать 2 кнопки: WebApp `/login` (подпись `open_label`) + url `consume_url` («Открыть на компьютере»).
- [ ] Никогда не показывать старую ссылку повторно — только свежую на каждый /start.
