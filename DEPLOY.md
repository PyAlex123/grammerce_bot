# Деплой бота Grammerce на VPS

Шпаргалка по обновлению бота на сервере после пуша в GitHub.
Claude ориентируется на этот файл, когда даёт рекомендации по пулу/рестарту.

## 0. Параметры (заполнить один раз)

- **Путь к папке на VPS:** `/opt/grammerce_bot` (compose-проект `grammerce_bot`, контейнер `grammerce_bot-bot-1`).
  - ⚠️ НЕ путать: `/var/www/grammerce` — это платформа (проект `grammerce`, `retail_saas_app`), другой репозиторий. `/var/www/grammerce_bot` — пустая папка, не используется.
- **Ветка прода:** `littleFix` (сервер уже на ней; коммиты пушим в неё же — мёрдж в `main` не требуется)
- **Имя сервиса в docker-compose:** `bot` (уточнить в `docker-compose.yml`)

## 1. Обновление кода и рестарт

```bash
# перейти в папку проекта
cd <ПУТЬ_К_ПАПКЕ>

# проверить, что нет случайных локальных правок
git status

# быть на нужной ветке и подтянуть код
git checkout <ВЕТКА_ПРОДА>
git pull origin <ВЕТКА_ПРОДА>

# пересобрать и перезапустить.
# ВАЖНО: --build обязателен — меняется код, а `docker compose restart`
# образ НЕ пересобирает. `up -d` также перечитывает .env (в отличие от restart).
docker compose up -d --build

# проверить логи
docker compose logs -f --tail=50 <СЕРВИС>
```

## 2. Как найти путь к папке проекта на VPS

Любой из способов (выполнять на сервере по SSH):

```bash
# А. Через docker — покажет проекты compose и путь к их конфигам
docker compose ls

# Б. Найти docker-compose.yml по всей системе
find / -name "docker-compose.y*ml" 2>/dev/null

# В. Найти папку по имени
find / -type d -iname "grammerce*" 2>/dev/null

# Г. Если контейнер бота запущен — вытащить рабочую директорию из его меток
docker inspect $(docker ps -qf "name=bot") \
  --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}'
```

Как только путь найден — вписать его в раздел 0, дальше все команды берутся оттуда.

## 3. Важные заметки

- **`--build` обязателен** при изменении кода. `restart` подхватывает только уже собранный образ.
- **`.env` перечитывается только через `up -d`**, а не `restart`.
- **Ветки:** код правок может лежать не в `main`. Перед `git pull` убедиться, что сервер на той же ветке, куда был пуш. Если прод тянет `main` — сначала смёржить фиче-ветку в `main` на GitHub.
- **Миграции БД:** если добавлялись новые колонки — после пула выполнить `alembic upgrade head` (create_all колонки не добавляет). Для правок только логики миграции не нужны.
- **Откат:** `git log --oneline -5`, затем `git checkout <хеш>` и снова `docker compose up -d --build`.

## 4. История правок

- `9b29bee` (ветка `littleFix`) — `/start register` ведёт на полное приветствие (убран лишний CTA-экран); скрыта ниша «Косметика». Миграции не требуются.
- `da8cbde` (ветка `littleFix`) — основная кнопка «Открыть платформу»/«Создать магазин» теперь открывает TWA (мини-апп) напрямую и больше не показывает отдельный экран «Создать магазин» (который прятал меню). Работает даже без `PLATFORM_WEBAPP_URL` (fallback на consume_url). Миграции не требуются.
  - **Рекомендация:** задать `PLATFORM_WEBAPP_URL` в `/opt/grammerce_bot/.env` (URL мини-аппа с авто-логином по initData) — тогда кнопка переоткрывается сколько угодно раз без `auth_expired`. Без него используется одноразовый consume_url (на каждый /start свежий).
